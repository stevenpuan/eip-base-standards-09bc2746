## P0-1 人員選單排除停用者 — `2359496`

已停用（離職）人員不再出現在可指派的選單中。

- 新增 `src/hooks/useUsers.ts`
  - `useActiveUsers()` — 只回 `status='active'`，**所有「選人」用途一律用這個**
  - `useAllUsers()` — 回全部（含停用），**只給 id→姓名顯示對照**
  - 兩者都回傳完整 useQuery 結果，`.data` / `.refetch()` 沿用原寫法
- 12 個檔案改造。同一頁常需兩者並用：`userMap` / `nameMap` 走 all，`users={...}` prop 走 active。
- `reports.tsx` 公告已讀率分母改為在職人數，避免被停用帳號稀釋。

**維持不過濾**（顯示對照，過濾掉會讓離職同仁的歷史紀錄姓名變空白）：
`work-log.tsx`、`quick-reports.tsx`、`feature-requests.index.tsx`

**未改動且不需改動**：

- `org.tsx` — 指派部門主管的 Select 早已有 `.filter(u => u.status === "active")`
- `feature-requests.$id.tsx` — 抓單一使用者，本來就該不分狀態

## P0-3 個人例行工作範本 — `80c1082`

新增 `src/routes/dashboard/eip/personal-routine.tsx`，路由 `/dashboard/eip/personal-routine`。

- 清單支援拖曳排序（原生 HTML5 DnD，寫回 `sort_order`）、時段 badge、週期轉自然語言、啟用開關
- 新增／編輯對話框：時段三選一、週期下拉連動（指定週幾出 chip、每月出日期輸入＋月底選項）
- `user_id` / `tenant_id` 由 `trg_personal_routine_defaults` trigger 自動補，**前端 insert 不要手動塞**
- 範本本身不產生 task，只在工作日誌 seed 時即時展開

## P0-4 工作日誌來源改造 — `3c66eb6`

修正「進行中任務不會出現在日誌」的問題。

- `buildSeed`（前端自查 task）→ `fetchSeed` 呼叫 RPC **`eip_worklog_seed(p_user_id, p_date)`**，規則統一在 DB
- UI 由兩區改為三區：上午例行／下午例行／特殊工作
  - 上午 = 個人例行範本（morning/allday）＋ 當日常態工作
  - 下午 = 個人例行範本（afternoon）
  - 特殊 = 我負責或協作且未完成 ＋ 今日完成 ＋ 未結案會議決議
- 日誌項目結構加上 `source` / `ref_id` / `req`；同步去重改用 `source+ref_id`，並跨三區比對
- `require_content` 生效：顯示「需填」標記，送出時擋下已勾選但未填執行內容的項目

**舊資料不需遷移**：既有日誌全部存在 `routine_morning`，新程式照原欄位讀，顯示結果與改造前一致。
