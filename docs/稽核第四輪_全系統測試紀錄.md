## 一、上線前必修（BLOCKER）

### B1 回收區整頁打不開 —— `eip_deleted_items` 欄位歧義

```
ERROR 42702: column reference "module_key" is ambiguous
```

`RETURNS TABLE(module_key text, label text, title text, deleted_at ...)` 的 OUT 欄位
在 plpgsql 裡就是變數，跟迴圈查詢的 `eip_deletion_policy.module_key` 撞名。
無論帶不帶 `p_module` 參數都直接炸掉 —— 也就是「回收區」頁面完全打不開。

- 修正：0133，迴圈查詢一律加表別名 `dp.`
- 驗證：`eip_deleted_items('eip_tasks')` 與 `eip_deleted_items()` 都正常回傳
- 這一項是我自己在跑全模組 smoke test 時才發現的，前三輪稽核都沒抓到

### B2 重新整理／書籤／LINE 連結會把有權限的人踢走

`auth.tsx` 拿到 session 就 `setLoading(false)`，但權限（roles → role_module_permissions
→ role_page_permissions）是之後兩段 round trip 才回來。`loading === false` 的那一刻
`perms = {}`、`roles = []`，`can()` 對**所有人（含 admin）**都回 false。

五個頁面在那一刻判斷 `!canView` → 直接 `<Navigate ... replace />`：
績效儀表板、異常缺失、部門例行彙總、臨時回報、報表中心（另外交接、個人例行、
週期任務只擋 `appUser`，同樣會中）。

從側邊欄點進去不會重現（那時 perms 已在記憶體），**但 F5、加書籤、從 LINE 推播
開連結一定中**，而且是 `replace` 導航，不會自己回來。

- 修正：`AuthContext` 新增 `permsLoaded` 旗標，權限載入完成（含失敗）才放行；
  8 個頁面的 guard 一律先等 `permsLoaded`
- 沒有 session 時直接放行，避免登出後卡在「載入中…」

### B3 行事曆整欄日期偏一天

`tasks.tsx` `CalendarView` 用 `d.toISOString().slice(0,10)`，而 `d` 是**本地午夜**。
台北 UTC+8 → 轉 ISO 會退回前一天，所有任務都被畫在「到期日的隔天」格子裡
（7/31 到期的跑到 8/1）。主管照行事曆排工就會排錯。

- 修正：改用 `d.toLocaleDateString("sv-SE")`（本地時區的 YYYY-MM-DD），
  與 `performance.tsx` / `anomalies.tsx` 既有寫法一致

### B4 結案摘要會被無聲清空

`closing_summary` 不在主清單的 select 欄位裡（typed client 不認新欄位），
開詳情時另外補讀一次；但初值是 `""`，而 `save()` 無條件寫
`closing_summary: closingSummary.trim() || null`。

在補讀回來之前（或補讀失敗時）改個優先級按儲存 → 主管寫的整段結案摘要變空，
畫面上不會有任何提示（欄位還沒 render 出來）。

- 修正：加 `summaryLoaded`，未載入完成時整個欄位不進 patch

## 三、強制檢查項二：外部服務的真實回應（LINE）

不看「我們有送出」，直接讀 `net._http_response` 的實際內容。

**近 12 小時（Edge Function 一律回 HTTP 200，真正的狀態在 body 裡）：**

| LINE 實際狀態 | 筆數 | 時間 | body |
|---|---|---|---|
| **429** | 37 | 07:40–13:15 UTC | `{"message":"You have reached your monthly limit."}` |
| 200 | 10 | 08:50–09:30 UTC | `{"sentMessages":[{"id":"624783018712105633",...}]}` |
| 500 | 4 | 08:03–09:59 UTC | `{"message":"Internal Server Error"}`（LINE 端偶發） |

**我在 15:52 UTC（台北 23:52）用 `eip_line_push_now()` 打了一發真實請求驗證，
回來還是 429 —— 月額度確認仍是用盡狀態。**

重點：**外層 HTTP 200 會掩蓋掉 LINE 的 429/500**。這個坑已經處理過了 ——
`eip_confirm_line_delivery()` 同時檢查 `r.status_code between 200 and 299`
**和** `eip_line_status(r.content) between 200 and 299`，才會蓋 `line_sent_at`。
本輪重新驗證這條沒有退化：

- 唯一會寫 `line_sent_at` 的函式就只有 `eip_confirm_line_delivery`（全庫 grep 確認）
- 12 小時內 60 筆通知、33 筆標記已送出，對應 10 次 LINE 200 —— 這是彙整推播
  一則涵蓋多筆通知的正常比例，**沒有假成功**
- 429 分支只設 `line_blocked_until = 下個月 1 號`、清掉 `line_request_id`，
  **不消耗重試次數**；三個進入點（`eip_emit_notification`、`eip_retry_urgent_line`、
  `eip_send_line_digests`）都會檢查 `line_blocked_until`，不會每 5 分鐘白打
- 目前佇列狀態：`line_pending = 0`、`blocked = 0`、`line_error = 0`

**要注意的時間點**：`line_blocked_until` 算的是 `date_trunc('month', now()) + 1 month`
= **2026-08-01 00:00 UTC = 台北 8/1 早上 8 點**，剛好是上線日早上。額度重置後
被封鎖的推播會一次補送。目前佇列是 0，所以不會爆量，但上線當天早上請留意。

   0134/0135 的閘門改回原本的 role 檢查即可（各一行）。

`app_user.role` 與 `eip_derive_app_role()` 已同步、`in_sync = true`），
實測兩人：

| | 個人績效可見人數 | 部門彙總 | 部門例行 | 異常KPI | 管轄部門 | 可見任務 |
|---|---|---|---|---|---|---|
| 吳巧蕙（冷凍課） | 2 | 1 部門 | 0（無資料） | 0（無資料） | 1 | 62 |
| 林佩杏（總務課） | 1 | 1 部門 | 0（無資料） | 0（無資料） | 1 | 51 |

（林佩杏是 1 是因為總務課目前只有她一位在職。）

順著這條線把整個組織表掃過去，又發現三件事：

### 9-1 有在職成員但沒有主管的部門 → 通知會整封消失（已加安全網）

`anomaly_filled` 的收件範圍是純 `['dept_manager']`。部門沒有主管時，
`eip_notification_recipients` 回傳**空集合** —— 同仁填報完成後沒有任何人收到通知，
缺失就停在「待確認」沒人處理，而且**不會留下任何錯誤紀錄**。這是最難發現的一種漏。

0136 修法：`dept_manager` 解析不到人時，① 往上找父部門的在職主管，
② 父部門也沒有才退到 `company_admin`。同時把「主管必須在職」明確寫進條件
—— 離職的 `manager_id` 現在等於沒有主管。

實測 15 個有在職成員的部門，`anomaly_filled` 全部找得到收件人：

- 分切課 → 曾于庭（父部門生產部主管）
- 衛管課 → 王儷瑾（父部門主管）
- 學校課 → steven、曾俊凱、曾于庭、方珮珊（本部門與父部門都沒主管，退到管理者）
- 電宰會計課 → 同上退到管理者
- 其餘 11 個部門 → 各自的主管一人，行為不變

這只是安全網。正解仍是把主管指派完整，指派好之後這段路徑就不會被走到。

### 9-2 電宰會計課的主管是離職帳號

`department.manager_id` 指向孫倩筠，但她的 `app_user.status = 'inactive'`。
她登不進來，所以那一課實際上沒有在職主管：異常缺失沒人能確認／結案。
0136 已讓通知不會消失，但**需要指派一位新主管**。

### 9-3 三個有人的部門沒有主管；一位有主管角色但沒管任何部門

| 部門 | 在職人數 | 主管 |
|---|---|---|
| 分切課 | 1 | **無** |
| 學校課 | 2 | **無** |
| 衛管課 | 1 | **無** |
| 業務部 | 0 | 無（空部門） |
| 財務部 | 0 | 無（空部門） |
| 行政部 | 0 | 王儷瑾（空部門） |

另外**曾義仁有 `dept_manager` 角色但沒有管任何部門** —— 他的部門績效／部門例行
頁面打得開，但因為列層過濾是 `eip_user_can_scope_dept()`，畫面會是空的。
不是壞掉，只是他會覺得「這頁沒東西」。要嘛指派部門給他，要嘛把角色降回 member。

### 9-4 交接的接手人推導沒有這個問題

實測無主管部門（分切課）的請假交接：`eip_handover_assignee` 回
**曾于庭（reason = parent_dept_manager）**，本來就有往上找的邏輯，不需要修。

**要你處理的（都在權限／組織設定頁，不需要改程式）：**

1. 電宰會計課 → 指派一位在職主管（現任是離職帳號）
2. 分切課、學校課、衛管課 → 指派主管
3. 曾義仁 → 指派部門給他，或把角色降回 member
4. 業務部、財務部、行政部 → 0 位在職成員，考慮停用以免下拉選單一直出現
