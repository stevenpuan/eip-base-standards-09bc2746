## 一、請假代辦：原型跟實作差在哪

| 原型要求 | 前一輪狀態 | 這一輪 |

| 入口：從快速回報獨立，**併入我的工作區** | 還在右下角 FAB | 工作區「代理事項」卡加「我要請假」；FAB 的請假頁改成導到同一份表單 |

| 代辦清單跟請假一起送出 | 只能事後一項一項加 | 同一張表單多列輸入（事項／指派／連結），一次送出 |

| **主管只收通知、不核准不簽核** | 已完成 | 表單與卡片的文案都再講一次，避免有人以為要送審 |

## 二、審查抓到的真 bug（已修）

前一輪的程式沒被審過（`quick-reports.tsx` 一次多 745 行）。這一輪跑對抗式審查，
逐條自己驗證後修掉以下這些。**agent 有兩項判斷是錯的，我沒照著改**（見第五節）。

### BLOCKER — 狀態顯示會說謊

`eip_lhi_rollup` 在「有一項被取消完成」時把請假單退回 `acknowledged`，
但正式庫裡 `acknowledged` 是**舊制「主管已確認」**留下的值（現有 24 筆），
前端把它顯示成「已完成」。結果：代辦退回未完成、`done_at` 已被清掉，
畫面卻還是綠色「已完成」。

→ 0145 改成退回 **`open`（待處理）**。不用改前端映射，舊資料的語意也不會被破壞。

### HIGH — 沒有代辦事項的請假單永遠關不掉

rollup 只在代辦項目有動靜時才跑，而且「0 項」不視為完成（否則等於自動結案）。
請假不一定有東西要交接 → 那張單永久停在「待處理」，主管的待辦感知被雜訊淹掉。

→ 0145 新增 `eip_close_leave_handover(p_report_id)`：**沒有未完成項目時**才能結案
（含完全沒有代辦的單），當事人／代理人／主管／管理者都能按。這不是審核。
前端在「代辦全完成」或「0 項」時才顯示「確認結案／無須交接，結案」。

### HIGH — 被逐項指派的代理人看不到請假單本身

`qr_read` 的條件只有「本人／company_admin／dept_manager 管轄部門」，
沒有涵蓋 `eip_quick_report.deputy_id`（這次的代理人）與
`eip_leave_handover_item.assignee_id`（被逐項指派的人）。
工作區查得到代辦、查不到所屬請假單 → 顯示「— 請假 未填區間」，
代理人不知道這是誰的假、哪幾天。

→ 0145 把這兩種人加進 `qr_read`；`qr_update_done` 也一併加
（原本它認的是 `app_user.deputy_id` 靜態代理人，新流程的人反而不在名單裡）。

### HIGH — 指定了代理人卻收不到通知

`leave_handover_created` 的收件範圍有 `deputy`，但那個 scope 解析的是
`app_user.deputy_id`（靜態代理人）。新流程的代理人存在 `eip_quick_report.deputy_id`，
完全不在收件人名單裡。

→ 0146 把 `new.deputy_id` 當 `p_extra_user_ids` 傳進去；另加
`trg_lhi_notify_assigned`，逐項指派給別人時也通知那個人（同一人多項會被去重吃掉，
不會一次塞十封）。實測：代理人收到 2 筆、總收件人 5 人（代理人＋主管們＋管理者）。

### HIGH — RLS 擋掉時「跳成功、實際沒動」

PostgREST 的 UPDATE／DELETE 被 RLS 擋掉時是 **0 筆 + error 為 null**，
只看 `error` 就會跳成功 toast，或完全沒反應。四處都中：

| 位置 | 原本 | 現在 |
|---|---|---|
| 指定代理人 | 已結案的單改不動，卻跳「已指定代理人」，選單再彈回 | `.select("id")` 看筆數，0 筆報「這張單已結案，或你沒有變更權限」 |
| 標記完成（遲到／事件） | 顯示條件是模組編輯權，RLS 是 submitter/主管/管理者，兩者不同軸 | 同上，報「不在你的權限範圍，或已經結案」 |
| 刪除代辦項目 | 靜默 0 筆卻跳「已刪除」 | 同上 |
| 移除 NAS 連結 | 非建立者按下去毫無反應、毫無提示 | 垃圾桶只對建立者／管理者顯示，並加筆數檢查 |

### HIGH — NAS 路徑被當成超連結，點了開到錯誤頁

`\\nas01\品保\2026` 是合法輸入（DB 也收），但三處用 `<a href>` 渲染。
瀏覽器的 URL parser 會把 `\` 正規化成 `/` → `//nas01/品保` → protocol-relative
→ 實際開到 `https://nas01/品保` 的 DNS 失敗頁。`file://` 從 https 頁面點也會被靜默封鎖。

→ 抽出 `lib/eip-url.ts` 的 `isLocalPath()`／`copyPath()`，**四處統一**改成
「點擊複製路徑」＋提示貼到檔案總管：`UrlLinks`、`quick-reports` 的代辦連結、
工作區代理事項卡、今日例行卡。

### MEDIUM — 前端 admin 判斷跟 RLS 不是同一個來源

`useAuth().isAdmin` 是 `roles.code = 'admin'`，RLS 用的是
`current_role_name()` = `app_user.role = 'company_admin'`。兩者都可能單邊成立：
看得到按鈕但按了 42501，或明明有權限卻看不到按鈕。
→ 代辦增刪與連結移除都改用 `appUser.role === "company_admin"`。

### MEDIUM — 樂觀更新的回滾會互相蓋掉

回滾原本是整批快照覆寫。快速勾 A 再勾 B，B 成功、A 失敗 → A 的回滾把含
「B 未完成」的舊快照寫回，B 的勾勾在畫面上跳回去。
→ 回滾只還原該筆。同時加**樂觀鎖**（`.is("done_at", null)` / `.not(...)`）：
方向是用本地快取算的，別人剛勾完成而我還是舊快取時，一點就會把它取消掉。

### MEDIUM — 今日例行的三個問題

- **單一全域 `busy`**：早上一次勾 5 項，第 2～5 次點擊被 `if (busy) return` 直接吃掉，
  畫面毫無反應（`disabled` 只給正在寫入的那一列）→ 改成 per-row `Set`。
- **儲存失敗會把剛打的字清掉**：失敗時 `reload()` 用 server 舊值整批取代，
  等於一個網路錯誤就把使用者寫的執行內容清空 → 失敗時**不 reload**，
  內容留在畫面上並提示「內容還在，請再試一次」。
- **debounce 沒 flush 就 unmount**：打完字 1 秒內關分頁／切頁（切視窗時 Chrome
  不會對 textarea 發 blur）整段丟掉 → cleanup 改成先 flush。
- 另外三個寫入路徑都補上 `invalidateQueries`：預設 `refetchOnWindowFocus` 為 true，
  切走再切回若 refetch 早於寫入落地，回來的舊快照會把樂觀狀態蓋回去且不再自我糾正。

### MEDIUM — 績效與部門例行彙總的口徑問題

- **績效 KPI 磚在載入中／失敗時顯示 0**：底下明細會寫「載入失敗」，
  但主管往上一看只讀到「本期沒有逾期、沒有未填報異常」→ 改成一律顯示「—」。
- **部門篩選只作用一半**：選了品保部，上方磚變品保，中間圖與下方部門表還是全公司
  → 同一畫面兩種範圍，截圖出去會被當成品保的數字。已一起過濾。
- **圖會隱去「完成 0、逾期 0」的部門**而表格照列 → 圖下方標註隱去幾個。
- **「近 N 天」實際取 N+1 天**（兩端都含）→ 兩頁都改。
- **未提交名單預設落在今天**：主管早上 9 點打開就看到全部門未提交、催填鈕可按
  → 等於鼓勵去催一份晚上才到期的日誌。改成預設選「最近一個不是今天的日期」。
- **催填只靠 `view` 權**（那是寫入動作）→ 改綁 `edit`，沒權限時按鈕明寫「沒有催填權限」。
- 催填 toast 原本寫死「今天已經催過」，實際催的是所選日期 → 帶上日期；
  部分成功（選 5 人回 3）也補上「另 2 人未發出」的說明。

### LOW — 反斜線轉義

`UrlLinks` 與 `TodayRoutineCard` 的 placeholder 多轉義一層（JSX 屬性字串**不做**
反斜線轉義），畫面上會印出 `\\\\NAS\\品保`；`TodayRoutineCard` 的 toast 少一層
（`\分` 是無效轉義會被吃掉），實際顯示「\伺服器分享資料夾」——教使用者打錯格式。
兩邊都修正。另外前端的正規表示式原本比 DB 的 check 嚴一格（要求兩個反斜線，
DB 只要一個），已對齊。

## 五、agent 說的但我沒照做的兩項
